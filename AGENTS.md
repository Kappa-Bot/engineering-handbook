# Engineering Handbook Repository Instructions

These instructions govern edits to this repository only.

- Treat the handbook as the canonical source for cross-repository engineering knowledge.
- Keep permanent agent context small; move specialized procedures into focused artifacts when they become real.
- Before adding a new rule, search this repository and `machine-readable/catalog.yaml` for an existing canonical topic.
- Do not promote external guidance directly into a MUST. Apply `governance/source-authority.md` and `governance/knowledge-promotion.md` first.
- Maintain one active canonical normative document per topic. Preserve meaningful superseded history instead of duplicating active guidance.
- Update `machine-readable/catalog.yaml` when internal artifacts are added, moved, superseded, or retired.
- Update `machine-readable/sources.yaml` when an external source is introduced or materially revalidated.
- Do not create empty taxonomy folders, speculative automation, portal infrastructure, or unrelated cleanup.
- Keep repo-specific knowledge out of this handbook unless it has been deliberately promoted as generalizable.
- Follow `policies/workspace-git-hygiene.md` and `policies/verification-definition-of-done.md` for changes and handoff.
