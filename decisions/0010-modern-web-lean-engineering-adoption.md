# Adopt modern web guidance and minimum-complete engineering

## Context and authorization

On 2026-11-17 the owner authorized a complete, discoverable incorporation of Modern Web Guidance and Ponytail into the Handbook, adapted to custom agents, internal CRMs and potentially connected public websites. The inspected base is `e576df0aa8f2b630e25407313df8bb8963a6317c`. This is authority to update the Handbook and its distribution source, not to deploy consumer applications or install third-party hooks globally.

The existing single Codex router, compiled context, Agency Agents specialization, Unslop reconstruction and security/data/verification owners remain applicable. A new upstream persona would compete with that system. A reference link alone would not make the methods operative or readily discoverable.

The [source assessment](../references/modern-web-ponytail-adoption-assessment.md) pins both projects, separates distribution from implementation versions, and records execution/privacy, licensing and evidence limits.

## Decision

1. **Make the useful methods active rules, not optional branding.** `pol-reuse-first` owns minimum-complete changes, caller/invariant tracing, justified reuse and root-cause ownership. `std-ui-ux-quality-baseline` owns current platform assessment, product browser support, framework-safe integration and verified fallback behavior. Apply these rules to relevant work regardless of whether the user names either upstream project.
2. **Keep one authority per topic.** `pb-modern-web-platform-workflow` operationalizes browser decisions and resource lookup; existing security, architecture/data, testing/release, performance and public-site legal owners still control their topics. [The connected-product map](../references/connected-product-resource-map.md) routes to those owners rather than inventing a second architecture for every CRM.
3. **Make resources findable through the existing distribution.** Extend the generic skill, semantic EN/ES classifier, phase-specific context, catalog and source registry. The bundle carries the local synthesis and immutable upstream locators. It does not vendor hundreds of guides, execute remote retrieval code or create another skill. A source name routes to its assessment; material browser work routes to the platform workflow; cross-surface product work routes to the boundary map.
4. **Reconcile modernity, simplicity and design.** Prefer a suitable canonical component/native capability with the smallest total ownership burden that meets the full contract. Newer APIs, shortest patches and existing components do not win by default. Authorized Unslop reconstruction can replace weak architecture of presentation; neither Ponytail nor this decision restores preservation-first aesthetics or cuts requested scope.
5. **Do not import executable behavior.** No Ponytail modes, session/prompt/subagent hooks, repository-map injection, background observers, new dependencies, `@latest`, npm execution, `.mwgrc` opt-ins or CI scans are activated. Any later runtime adoption must pass `std-dependency-supply-chain-baseline` against the actual artifact and effective execution/data boundary. Publication of this decision is not that approval.
6. **Protect the real product boundaries.** Browser simplification cannot remove server authorization, tenant isolation, constraints, atomicity, idempotency, confirmation or truthful persistence feedback. A public form, authenticated CRM and agent tool can share domain behavior without sharing credentials, data exposure or authority. No generic provider choice, customer retention period, personal coding entitlement, A2A/WebMCP integration or new external side effect is authorized here.
7. **Measure without manufactured savings.** Upstream evaluations justify examining the methods, not copying percentages into delivery claims. Tests are selected by failure consequence, not a one-test ceiling; source lines, tokens and patch size are diagnostic signals, not quality gates. Reviews include affected consumers outside the diff and report uncovered evidence honestly.

## Alternatives rejected

- Installing both upstream skills unchanged: conflicting routing/authority, mutable runners, telemetry and hook behavior would become part of every affected session without a product need.
- Reference-only adoption: leaves ordinary tasks and installed bundles unable to find or apply the new contract reliably.
- Replacing current standards with upstream prompts: loses existing risk, legal, accessibility, design and delivery guarantees.
- New global frontend framework, service topology or shared CRM package: neither source demonstrates that such a migration is necessary.
- Forced modernization or fewer lines everywhere: churn and hidden regressions are not acceptance criteria.

## Acceptance and maintenance

Verify canonical integrity, immutable resource paths, deterministic compilation/freshness, EN/ES routing and negatives, source provenance, all phases, context budgets and actual execution from an isolated installed bundle. Review the combined cases: native dialog in React, dense CRM tables, public intake into a tenant-scoped API, authorized agent writes, deletion of apparently dead consumers, and an audit that must stay read-only.

These checks establish Handbook/distribution behavior, not deployed product compliance. Consumers use the existing authorized refresh, then run bundle `Check` and representative context requests from the installed `references/` directory. A source merge is not proof that a workstation or every consumer was refreshed.

Review by 2027-02-17, or earlier on source/license changes, framework/browser incompatibility, unsafe runtime behavior, false routing or contradictory product evidence. Upgrade pins and adaptations together; never silently chase a moving branch. Retain source credits and change notices in the assessment.
